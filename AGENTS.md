# MEDCORE

## Контекст

Курсовой проект Яковлева Артёма Сергеевича, группа 5996, по дисциплине «Технология разработки и защиты баз данных». Сдача 11.05.2027. Руководитель Цымбалюк Лариса Николаевна. Источники и референсы сохранены в materials/originals; контрольные суммы в materials/manifest.json.

## Порядок работы

- Пользователь явно разрешил команду субагентов и её перераспределение в зависимости от текущих задач. При независимых крупных задачах делегировать с отдельным владением файлами; общую интеграцию и проверку выполняет ведущий агент.
- ТЗ и принятые решения: docs/project/decisions.md, requirements.md. Статус и следующий этап: docs/project/roadmap.md. Не выдавать запланированное за реализованное, синтаксическую проверку за пройденный пользовательский тест, PGlite за проверку многопользовательского сервера.
- PostgreSQL Database First. SQL-миграции — источник схемы; не дублировать управление схемой независимыми EF-миграциями.
- Все таблицы и объекты MEDCORE — в схеме project. Старый космический проект перенесён в space_archive; пользователь отменил удаление. Эти данные не изменять. GUC medcore.actor_user_id/request_id и PREPARE medcore_q01–12 сохраняют префикс приложения.
- Исходные материалы не изменять. Для сдачи готовить отдельные документы. Прошлогодний курсовой — образец, а не источник фактов о MEDCORE.
- Не выдумывать подписи, допуск, согласование руководителя, результаты испытаний и библиографические источники. Титульные реквизиты и шифры сверять с актуальным заданием.
- Тёмный Glassy Dashboard V5, полупрозрачные панели, мягкие блики, плавные анимации; плотный читаемый фон медицинских таблиц и форм. Рабочие данные и показатели приходят из API.
- Учебные данные вымышленные. Пароли и строки подключения хранить только в игнорируемых локальных настройках; не печатать секреты в отчётах, логах и сообщениях агентам.
- Внешнюю учебную БД использовать только в выделенной пользователю базе/схеме. До первой записи проверить текущую базу, права и отсутствие пересечения с чужими объектами. Не очищать общие схемы и не менять существующие чужие таблицы.

## Проверка БД

Изолированная проверка: `pnpm install --frozen-lockfile`, затем `pnpm test:database`. Она создаёт новую PGlite в памяти, исполняет миграции и SQL-проверки, пишет docs/database/checks/pglite-report.json. Это не подключается к учебному серверу. Для сети, прав и конкуренции нужны отдельные интеграционные испытания настоящего PostgreSQL.

Миграции 001–003 уже применены на учебном PostgreSQL 18; хеши в docs/database/checks/educational-deployment.json. Не редактировать применённые миграции: исправления проводить новыми файлами. Скрипт первоначального применения намеренно откажет при повторном запуске. .env содержит фактический доступ; не печатать его. Сервер SSL не поддерживает; это зафиксировано в database/README.md.

Миграция 002 использует сериализацию предметных записей и READ COMMITTED; ограничения и причины описаны в docs/database/business-rules.md. Не менять волатильность проверяющих функций на STABLE/IMMUTABLE. Операции поступления, перевода и выписки должны сохранять непрерывное покрытие интервалов на COMMIT.
