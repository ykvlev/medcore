# База данных MEDCORE

## Размещение

Все таблицы, представления, пользовательские типы, процедуры и функции MEDCORE размещаются в схеме `project` по прямому требованию пользователя. Учебный сервер — PostgreSQL 18.0. Расширения `btree_gist` и `pg_trgm` установлены в `public`; предметных таблиц MEDCORE вне `project` нет.

Предыдущие пять таблиц космического проекта и представление перенесены в `space_archive` без удаления строк. Сверка количества записей и работоспособности представления сохранена в `docs/database/checks/space-archive-transfer.json`.

## Миграции

| Файл | Содержание |
|---|---|
| 001_initial_schema.sql | 47 таблиц предметной области и доступа, ключи, ограничения, домен, ENUM и индексы |
| 002_business_rules.sql | 48-я служебная таблица очереди, отложенные проверки целостности, защита исторических связей |
| 003_stored_objects.sql | 3 представления, 4 процедуры пациента, 2 расчётные функции, аудит и версия карточки |

Всего: 48 таблиц, 3 представления, 4 процедуры и 11 функций, включая служебные триггерные функции. Описание модели и семантики находится в `docs/database/model.md`, `business-rules.md` и `sql-objects.md`.

Каждая SQL-миграция имеет собственные BEGIN/COMMIT для отдельного запуска. Скрипт первоначального применения на учебном сервере снимает только эти внешние обёртки и выполняет все три файла в одной общей транзакции. Он отказывается работать с непустой `project` и не удаляет объекты. Повторно запускать его на развёрнутой схеме не нужно. Дальнейшие изменения оформляются новыми миграциями.

## Проверки

`pnpm test:database` создаёт новую PGlite в памяти. Он исполняет три миграции, подготавливает и выполняет двенадцать запросов на пустых данных, проверяет базовые ограничения и запускает обе группы SQL-проверок с временными фикстурами. Отчёт: `docs/database/checks/pglite-report.json`.

На учебном сервере три миграции применены успешно. Двенадцать PREPARE скомпилированы; обе группы SQL-проверок выполнены успешно. Тестовые строки откатились; значения последовательностей могут увеличиваться после ROLLBACK, поэтому пропуски идентификаторов допустимы. Отчёт: `docs/database/checks/educational-deployment.json`.

Дополнительно два независимых серверных соединения прошли 12 утверждений проверки конкурирующих трудоустройств, свежего подтверждённого состояния и отказа неподдерживаемого уровня изоляции. Адресная очистка фикстуры прошла. Отчёт: `docs/database/checks/server-concurrency-report.json`. Проверены конкретные сценарии, а не все варианты конкуренции.

Эти результаты не являются пройденными пользовательскими тестами: API и интерфейс ещё не реализованы. Права будущей роли API, полный демонстрационный набор и резервное восстановление проверяются отдельно.

## Подключение

`.env.example` задаёт перечень параметров; фактический `.env` хранится локально и исключён из контроля версий. Пароль не включается в SQL, документы и отчёты. Учебная роль не суперпользователь и не может создавать роли БД. Роль API с минимальными правами потребуется согласовать с доступными средствами сервера; пользовательское разграничение ролей будет выполняться приложением независимо от этого ограничения.

Учебный сервер не поддерживает SSL, что подтверждено попыткой защищённого соединения. В локальных настройках для него выбран обычный режим. HTTPS и TLS для иной сетевой эксплуатации задаются отдельно; текущая конфигурация не является зашифрованным каналом БД.
