## Ближайший проверяемый результат

На учебном PostgreSQL 18 развёрнуты три миграции в схеме `project`, выполнены обе группы SQL-проверок и отдельная проверка двух одновременных серверных сессий. Следующий результат — воспроизводимые демонстрационные данные и сверка агрегатов. До подключения API нужно выбрать способ минимальных привилегий в условиях учебной роли без CREATE ROLE и расширить конкурентные проверки на операции размещения пациентов. Транзакционная выписка, перенос внутри больницы, ограничения вместимости, научных званий, совместительства и лабораторных связей уже проверены SQL-фикстурой.

## Обязательные сценарии приёмки

TC-01 — регистратор создаёт пациента, запись видна в БД и интерфейсе.

TC-02 — изменение контактов сохраняется и отражается в аудите.

TC-03 — поиск по фрагменту ФИО возвращает соответствующие записи.

TC-04 — госпитализация при отсутствии мест отклоняется без частично сохранённых данных.

TC-05 — прямой запрос регистратора на изменение диагноза получает отказ, запись не меняется.

UT-01 — правила допустимого размещения и занятой койки. UT-02 — запрет изменения диагноза без медицинских полномочий. Дополнительно интеграционные испытания проверяют реальные ограничения PostgreSQL, конкуренцию транзакций и восстановление резервной копии.
