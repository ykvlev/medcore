# Контракт расширения: роли, области, МКБ-10, история болезни

Документ фиксирует решения этапа 3. Коды ролей и маршруты обязательны для сервера, клиента и миграции.

## Новые роли

| Код | Название | Область | Права |
|---|---|---|---|
| `chief_physician` | Главный врач | больница (`organization_id`) | персонал, структура, все пациенты больницы, диагнозы, госпитализации, лаборатории, отчёты больницы; управление сотрудниками |
| `deputy_chief_physician` | Заместитель главного врача | больница | то же чтение и отчёты, структуру не меняет |
| `head_of_department` | Заведующий отделением | больница + отделение (`department_id`) | чтение пациентов больницы, статистика и занятость своего отделения, персонал отделения; медицинские записи не создаёт |
| `minister_of_health` | Министр здравоохранения | город (без персональных данных) | агрегированные отчёты и показатели по всем учреждениям, справочник организаций |
| `governor` | Губернатор | регион (без персональных данных) | то же, что министр: сводные показатели и отчёты |

Существующие роли не меняются: `system_admin`, `organization_admin`, `doctor`, `registrar`, `lab_staff`, `analyst`.

Правила:
- Персональные данные пациентов недоступны `minister_of_health`, `governor`, `system_admin`, `analyst`.
- `chief_physician`/`deputy_chief_physician` видят пациентов только своей больницы (прикрепление к поликлинике этой больницы, открытый случай или госпитализация в её отделениях).
- `head_of_department` — те же пациенты, но только чтение; его `department_id` сужает статистику и списки персонала.
- `minister_of_health` и `governor` получают данные только через агрегирующие отчёты; различия — в подписи рабочей области, права одинаковые.

## Схема (миграция 004)

- `project.roles`: добавить пять строк с кодами выше.
- `project.employee_categories`: добавить `chief_physician`, `deputy_chief_physician`, `head_of_department`, `minister`, `governor`.
- `project.user_organization_scopes`: добавить nullable `department_id bigint REFERENCES project.departments(id)`; CHECK: `department_id` допустим только для `head_of_department`.
- `project.diagnoses`: добавить `chapter text` (глава МКБ-10, например «IX») и `is_active boolean NOT NULL DEFAULT true`; уникальность `code` уже есть.
- Демонстрационные пользователи: `chief`, `deputy`, `head`, `minister`, `governor` (пароль тот же, что у остальных).
- МКБ-10: заменить пять учебных `DEMO-01…05` на реальные коды и добавить не менее 40 распространённых кодов МКБ-10 (код + русское название + глава). Существующие ссылки `case_diagnoses.diagnosis_id` сохраняются.

## API

- `GET /api/diagnoses?search=&limit=` → `{ "items": [ { "id": 1, "code": "I10", "name": "Эссенциальная гипертензия", "chapter": "IX" } ] }`. Доступ: все, кто может читать пациентов, плюс `doctor`, `chief_physician`, `deputy_chief_physician`.
- `GET /api/roles` (для админки) остаётся `/api/admin/roles`, отдаёт и новые роли.
- `GET /api/patients/{id}` — в истории добавить медицинские записи (`medical_record_entries`) и коды МКБ у диагнозов: элемент истории `{ id, type: "diagnosis", title: "I10 — Эссенциальная гипертензия", occurredAt, description }`.
- `GET /api/reports/*` и `/api/dashboard/summary` — доступ для `chief_physician`, `deputy_chief_physician`, `minister_of_health`, `governor`; для министра и губернатора агрегаты по всем организациям, без персональных полей.
- `GET /api/employees` — `chief_physician`, `deputy_chief_physician`, `head_of_department` видят сотрудников своей области; `head_of_department` — только своего отделения.
- `POST /api/patients/{id}/diagnoses` — без изменений, `diagnosisId` из справочника МКБ.

## Клиент

- Навигация строится по ролям: главный врач и заместитель видят «Персонал», «Стационар», «Отчёты», «Пациенты»; заведующий — «Персонал», «Стационар», «Отчёты» (без создания записей); министр и губернатор — «Организации» и «Отчёты» с пометкой «Сводные данные города/региона».
- Карточка пациента: вкладка/блок «История болезни» с хронологией: диагнозы с кодом МКБ, медицинские записи, госпитализации, исследования.
- Форма диагноза: поиск по коду и названию МКБ-10, выбор из списка.
- Админка: новые роли в списке, область `department` для заведующего.

## Ограничения

- Министр и губернатор не получают персональных карточек; попытка — 403.
- `head_of_department` не создаёт и не изменяет медицинские записи.
- Новые роли не получают доступа к управлению пользователями (это только `system_admin`).
