# Комплект документации и правила оформления

## Как используются предоставленные стандарты

Это рабочая карта по содержанию полученных PDF. Она не устанавливает правовой статус стандартов и не заменяет отдельные указания колледжа. Общие правила оформления отчёта нельзя автоматически применять к каждой форме программной документации.

| Документ | Применение в MEDCORE |
|---|---|
| ГОСТ Р 59793—2021 | Стадии и этапы создания автоматизированной системы; рабочий план |
| ГОСТ 34.601—90 | Предоставленный образец описания стадий АС; сопоставление с Р 59793 |
| ГОСТ 34.602—2020 | Структура ТЗ на систему в целом и проверяемость требований |
| ГОСТ 34.201—2020 | Виды, комплектность и обозначения документов АС |
| ГОСТ 19.001—77 | Общие положения ЕСПД |
| ГОСТ 19.101—2024 | Виды программ и программных документов |
| ГОСТ 19.201—78 | ТЗ на программное изделие; при необходимости согласование программной части |
| ГОСТ 19.202—78 | Спецификация программного изделия; не автоматическая замена ведомости курсового |
| ГОСТ 2.105—2019 | Общие требования к текстовым документам ЕСКД в применимой части |
| ГОСТ 7.32—2017 | Структура отчёта и правила его оформления в применимой к записке части |

В предоставленных копиях обозначения подтверждены по титульным данным: файлы `ГОСТ 19.101-24.pdf` и `ГОСТ 34.602-20.pdf` содержат стандарты 2024 и 2020 годов. Наименование файла не используется как полное библиографическое обозначение. Не утверждается без отдельной проверки, что любой старый стандарт автоматически заменён другим из комплекта.

ТЗ версии 1.0 подробно описывает продукт, но его 20 разделов не повторяют структуру ТЗ по ГОСТ 34.602—2020. При подготовке сдаваемого ТЗ требования будут распределены по десяти обязательным разделам стандарта с сохранением исходного содержания. Основания разработки, порядок разработки, подготовка объекта к вводу, контроль и приёмка должны быть явно описаны. Факт утверждения преподавателем не придумывается.

## Параметры для подготовки основной записки

По п. 6.1.1 предоставленного ГОСТ 7.32—2017 для отчёта: А4, односторонняя печать, полуторный интервал; поля 30 мм слева, 15 мм справа, по 20 мм сверху и снизу; отступ первой строки 1,25 см. Шрифт чёрный, не меньше 12 пт, рекомендуется Times New Roman. Для рабочего шаблона MEDCORE выбирается Times New Roman 14 пт; именно 14 пт — проектный выбор с учётом образца, а не дословное требование этого пункта.

По пп. 6.2–6.3: структурные элементы и разделы начинаются с новой страницы; страницы нумеруются сквозным образом, титульный лист учитывается без напечатанного номера; для отчёта номер помещается внизу по центру. По п. 6.17 приложения начинаются с новой страницы, имеют обозначение и заголовок; ссылки на них присутствуют в основном тексте.

В прошлом образце записки поля отличаются: около 30 мм слева, 20 мм справа, 10 мм сверху, 31,8 мм снизу. Это может быть связано с оформлением рамок. До проверки требований колледжа старые поля и рамки не объявляются обязательными. Отдельные файлы образца имеют другие поля и стили, поэтому слепое копирование всех шести файлов дало бы неоднородный комплект.

На скриншоте аннотация, ведомость и план-график отмечены как ненумеруемые самостоятельные документы. Это указание о комплекте следует отделять от сквозной нумерации собственно пояснительной записки. Вопросы рамок, основной надписи, шифра и кода МДК остаются для сверки с актуальным заданием.

## Структура пояснительной записки

Введение.

1. Постановка задачи и анализ предметной области: объекты автоматизации; текущие процессы; цель и задачи; функциональные и нефункциональные требования; обзор аналогов на проверенных источниках.
2. Проектирование базы данных: сущности и атрибуты; связи; функциональная и информационная модели; реляционная модель; нормализация; ограничения и типы данных.
3. Создание объектов базы данных: DDL; индексы; представления; процедуры; функции; триггеры; пользовательские объекты; запросы с примерами результатов.
4. Проектирование и создание приложения: архитектура; обоснование технологий; сервер; клиент; сценарии CRUD; поиск; отчёты; результаты тестирования.
5. Методы защиты данных: угрозы; аутентификация; авторизация; защита запросов; аудит; резервное копирование; проверки ограничений доступа.

Заключение. Список использованных источников. Приложения.

Текст о реализации, количестве объектов и успешных испытаниях заполняется по фактическим результатам. Число страниц, рисунков, таблиц и источников для аннотации считается после окончательной сборки.

## Предварительное распределение приложений

| Обозначение | Содержание |
|---|---|
| А | Функциональная модель IDEF0, декомпозиция, Use Case, ER, IDEF1X, физическая схема и диаграмма классов |
| Б | SQL-код объектов БД и запросов |
| В | Функциональные тест-кейсы и результаты автоматизированных тестов |
| Г | Руководства пользователя и администратора |
| Д | Программный код |
| Е | Эскизы окон и визуальная концепция |
| Ж | Скриншоты административных форм |
| И | Скриншоты пользовательских сценариев, поиска и примеры отчётов |
| К | Отчётные формы предметной области, если используются при анализе |

Первые шесть обозначений соответствуют расположению основных групп на скриншоте задания: А — диаграммы, Б — SQL, В — тесты, Г — руководства, Д — программный код, Е — эскизы. Последующие обозначения предварительные. Окончательный порядок будет согласован с порядком ссылок в тексте и фактическим комплектом.

## Самостоятельные материалы сдачи

Задание на курсовое проектирование; аннотация; пояснительная записка; план-график; ведомость; электронный комплект кода, SQL и инструкции запуска; презентация. Отзыв и допуск оформляет руководитель в установленном порядке. В ведомости перечисляются реальные материалы и фактическое количество листов; заранее выдуманное количество страниц не проставляется.
