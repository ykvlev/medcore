# Руководство администратора MEDCORE

**Назначение.** Руководство описывает развёртывание, запуск и сопровождение учебной системы MEDCORE: требования к среде, базу PostgreSQL, резервное копирование и восстановление, запуск сервера и клиента, пользователей, роли, аудит, ограничения и действия при сбоях.

**Область применения.** MEDCORE — учебный локальный комплекс с вымышленными данными. Документ не является инструкцией по промышленной эксплуатации медицинской системы. Он подготовлен по фактическому состоянию комплекта и отчётов о проверках на 30 октября 2026 г. и не подтверждает прохождение приёмочных испытаний.

## 1 Общие сведения и требования к среде

MEDCORE состоит из React-клиента, ASP.NET Core API и PostgreSQL. Клиент отдаёт Vite на порту 5173, API слушает 5180 и обращается к базе по строке подключения. Все объекты MEDCORE находятся в схеме `project`; схему `space_archive` изменять и удалять нельзя.

Владелец схемы технически может отключить защитные триггеры — доступ к этой учётной записи должен быть ограничен.

## 2 Развёртывание базы данных

### 2.1 Подготовка и файл .env

1. Создайте выделенную учебную базу и схему `project`; схема должна принадлежать учётной записи, применяющей миграции.
2. Установите расширения `btree_gist` и `pg_trgm`.
3. Проверьте подключение: `psql -h <хост> -U <пользователь> -d <база> -c "select version();"`.
4. Скопируйте `.env.example` в `.env` и заполните локально: `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGSSLMODE=disable`, `MEDCORE_DEMO_PASSWORD`.

`.env` исключён из контроля версий. Не включайте его в отчёт, архив или репозиторий. API не читает `.env` сам: переменные загружает `tools/run-dev.mjs`; при прямом запуске `dotnet` задайте их в окружении. Загрузить файл в текущую сессию PowerShell без вывода секретов можно так:

```powershell
Get-Content .env | Where-Object { $_ -match '^[A-Za-z_][A-Za-z0-9_]*=' } | ForEach-Object {
    $name, $value = $_ -split '=', 2
    Set-Item -Path "Env:$name" -Value $value
}
```

### 2.2 Миграции

Источник схемы — SQL-миграции `001_initial_schema.sql`, `002_business_rules.sql`, `003_stored_objects.sql`; каждая имеет собственные `BEGIN`/`COMMIT`. Применяйте по порядку. Для выделенной учебной базы:

```powershell
node tools\deploy-educational-db.mjs
```

Скрипт отказывается работать с непустой схемой `project`, проверяет принадлежность схемы, выполняет миграции одной общей транзакцией, компилирует двенадцать запросов и запускает SQL-проверки с откатом. Отчёт: `docs/database/checks/educational-deployment.json`.

**Ограничение.** В скрипте жёстко закреплены база `db_a_s_yakovlev` и пользователь `a-s-yakovlev`. Для другой базы применяйте файлы через `psql` с `ON_ERROR_STOP=1`:

```powershell
psql -h <хост> -U <пользователь> -d <база> -v ON_ERROR_STOP=1 -f database/migrations/001_initial_schema.sql
psql -h <хост> -U <пользователь> -d <база> -v ON_ERROR_STOP=1 -f database/migrations/002_business_rules.sql
psql -h <хост> -U <пользователь> -d <база> -v ON_ERROR_STOP=1 -f database/migrations/003_stored_objects.sql
```

Повторно запускать скрипт на развёрнутой схеме не нужно. Применённые миграции не редактируются: исправления оформляются новыми файлами `004_*.sql` и далее.

## 3 Резервное копирование и восстановление

### 3.1 Создание копии

```powershell
node tools\backup-db.mjs --label=before-update
```

Скрипт создаёт логическую копию схемы `project` в формате `pg_dump` custom и манифест `.manifest.json`: время, размер, SHA-256, версии PostgreSQL и `pg_dump`, схемы, расширения, количество объектов, контрольные количества строк ключевых таблиц, длительность и предупреждения. Пароль в манифест не попадает. Схема `space_archive` по умолчанию не копируется; для неё используется `--include-archive`. Каталог задаётся `--out-dir`, метка — `--label` (буквы, цифры, дефис, до 40 символов).

Скрипт читает `.env`, требует `PGPASSWORD`, не запрашивает пароль интерактивно и не печатает его. `pg_dump` ищется в `PATH` и стандартных каталогах; явный путь задаётся `PG_DUMP`. Если `pg_dump` не найден, копия не создаётся. Предупреждения о циклических зависимостях схемы не отменяют успешную копию и фиксируются в манифесте.

Проверка: файл не пуст, размер совпадает с манифестом, SHA-256 совпадает с `sha256`, в манифесте ожидаемые схемы и ненулевые количества. Оглавление копии можно просмотреть без восстановления:

```powershell
& "C:\Program Files\PostgreSQL\18\bin\pg_restore.exe" --list backups\<файл>.dump
```

Копия содержит персональные данные и хеши паролей. Храните её вне рабочего каталога базы и ограничьте доступ.

### 3.2 Восстановление

Восстанавливайте только в отдельную тестовую базу. Скрипт `tools/restore-db.mjs`:

- требует явное `--database=<тестовая_база>` и отказывается от рабочей БД из `.env`, а также от `postgres`, `template0`, `template1`;
- проверяет размер и SHA-256 копии по манифесту и читает оглавление через `pg_restore --list`;
- отказывается, если в целевой БД уже есть схемы `project` или `space_archive`;
- выполняет `pg_restore --no-owner --no-privileges --single-transaction --exit-on-error`;
- сверяет 10 ключевых таблиц, 3 представления, 4 процедуры, 48 таблиц, 11 функций и расширения;
- пишет JSON-отчёт.

```powershell
& $node tools\restore-db.mjs --dump=backups\<файл>.dump --database=medcore_restore_check --report=docs\database\checks\backup-restore.json
```

Флаг `--create` создаёт БД только при праве `CREATEDB`. У учебной роли его нет, поэтому пустую БД создаёт администратор СУБД и назначает владельцем учебную роль: `CREATE DATABASE medcore_restore_check OWNER <учебная_роль>;`. Имя и роль берите из `.env`; не подставляйте рабочую БД. Затем запустите восстановление без `--create`. В отчёте ожидаются `result = passed`, все `match = true`, 48 таблиц, 3 представления, 4 процедуры, 11 функций и оба расширения.

**Статус на 30 октября 2026 г.** Копия создана: 381 634 байта, SHA-256 `9d09149d…`, 48 таблиц, 3 представления, 4 процедуры, 11 функций. На учебном сервере восстановление не выполнено: нет права `CREATE DATABASE` (SQLSTATE 42501). В изолированном PostgreSQL 18.6 восстановление прошло: 10/10 ключевых таблиц, 3/3 представления, 4/4 процедуры, 48 таблиц, 11 функций, расширения установлены. Это подтверждает переносимость копии и работу скрипта, но не снимает ограничение сервера.

Регламент: копия перед миграцией или изменением структуры, проверка восстановления не реже раза в месяц, хранение не менее трёх месяцев с ограниченным доступом. Автоматического расписания нет.

## 4 Запуск сервера и клиента

### 4.1 Установка и совместный запуск

```powershell
pnpm install --frozen-lockfile
pnpm --dir frontend install --frozen-lockfile
node tools\run-dev.mjs
```

Запускатель загружает `.env`, собирает API, поднимает сервер на `http://127.0.0.1:5180` и клиент на `http://127.0.0.1:5173`. Остановка — `Ctrl+C`. Режимы: `--no-build` (без пересборки API), `--backend-only`, `--frontend-only`.

Раздельный запуск: соберите API командой `dotnet build backend\Medcore.Api\Medcore.Api.csproj`, запустите `dotnet run` и `pnpm --dir frontend dev`. При этом API не читает `.env`: задайте `ConnectionStrings__Medcore` или `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGSSLMODE` в окружении. Часовой пояс подключения — Europe/Moscow, `SearchPath` — `project,public`.

### 4.2 Проверка и порты

1. `http://127.0.0.1:5180/health` → `{"status":"ok"}`.
2. `http://127.0.0.1:5180/swagger` → описание API загружается.
3. `http://127.0.0.1:5173` → вход и обзор с ненулевыми показателями.

`/health` подтверждает только ответ HTTP-процесса, а не доступность базы. Если API отвечает, а разделы дают 503, проблема в подключении к PostgreSQL.

Vite использует строгий порт 5173 и прокси `/api` на 5180. CORS разрешает только `http://localhost:5173` и `http://127.0.0.1:5173`. При смене порта API или клиента нужно одновременно изменить цель прокси в `frontend/vite.config.ts` и разрешённые источники CORS в `backend/Medcore.Api/Program.cs`, иначе браузер не получит API.

## 5 Пользователи, роли и аудит

### 5.1 Учётные записи

Раздел `/admin` доступен только `system_admin`; проверка выполняется на сервере. Создание: «Администрирование» → «Пользователи» → «Создать пользователя» → логин (3–128 символов без пробелов), пароль (8–128), при необходимости идентификатор сотрудника, хотя бы одна роль и область → «Создать».

**Таблица 3 — Роли и области действия**

| Роль | Код | Область |
|---|---|---|
| Системный администратор | `system_admin` | Без области |
| Администратор организации | `organization_admin` | Учреждения |
| Врач | `doctor` | Учреждения и связанные медицинские случаи |
| Регистратор | `registrar` | Поликлиники |
| Сотрудник лаборатории | `lab_staff` | Лаборатория |
| Аналитик | `analyst` | Учреждения, отчёты |

Ограничения: логин уникален; сотрудник привязан только к одной учётной записи; системному администратору область не назначается; лаборатория допустима только для `lab_staff`; для одной роли указывается либо учреждение, либо лаборатория; повтор роли с той же областью запрещён. Пароль хранится как хеш ASP.NET Identity V3 (PBKDF2-HMAC-SHA512, 210 000 итераций, случайная соль).

Отключение отзывает все сессии пользователя и сохраняет роли; включение возвращает доступ. Нельзя отключить себя и лишить себя роли `system_admin` — сервер вернёт 409. Смены и сброса пароля через интерфейс или API нет: создайте новую учётную запись, назначьте роли, старую отключите. Не редактируйте хеш вручную.

### 5.2 Роли через API

Изменение набора ролей существующего пользователя в интерфейсе не выведено. Оно выполняется запросом:

```http
PUT /api/admin/users/{id}
Content-Type: application/json

{
  "isActive": true,
  "roles": [
    { "role": "analyst", "organizationId": null, "laboratoryId": null }
  ]
}
```

Запрос требует сессии `system_admin`. Набор ролей и областей заменяется целиком, а не дополняется. Сохраните текущий набор перед изменением. Операция пишется в аудит как `role_change`.

### 5.3 Журнал аудита

Вкладка «Журнал аудита»: фильтры «С даты», «По дату», «Действие» (точное совпадение кода), страницы по 20 событий, сначала новые. Период трактуется включительно по Europe/Moscow; без дат показывается весь доступный период.

**Таблица 4 — Коды действий журнала аудита**

| Код | Смысл |
|---|---|
| `login`, `logout` | Вход и выход; неудачный вход — `outcome=failure` |
| `insert`, `update`, `delete` | Создание, изменение, удаление объектов |
| `read` | Открытие карточки пациента |
| `role_change` | Изменение ролей |
| `transfer`, `attending_change`, `discharge` | Перевод, смена врача, выписка |

Что искать: серии неудачных `login` (попытки подбора; логин автора может быть пустым), `role_change` (расширение доступа), `update` по `user` с `is_active`, `read` по пациентам вне обычной области, `transfer`, `attending_change`, `discharge` с неожиданным автором или временем. Экспорта журнала нет; записи не удаляйте вручную.

## 6 Ограничения учебной среды

**Таблица 5 — Ограничения учебной среды**

| Ограничение | Следствие | Что делать |
|---|---|---|
| Нет SSL у PostgreSQL | Канал «API — БД» не шифруется | Только локально или в доверенном сегменте; TLS настраивать отдельно |
| Нет HTTPS у приложения | Cookie не получает `Secure` при HTTP | Не выставлять в интернет; настроить reverse proxy и HTTPS |
| Нет `CREATE ROLE` | Нельзя создать малопривилегированную роль API | Работать под владельцем схемы, разграничение — в приложении |
| Владелец схемы может отключить триггеры | Возможен обход ограничений | Ограничить доступ к учётной записи владельца |
| Скрипт развёртывания привязан к учебной базе | Не работает на другой базе | Применять миграции через `psql` |
| Нет права `CREATE DATABASE` | Восстановление на учебном сервере не выполнено (SQLSTATE 42501) | Администратор СУБД создаёт пустую тестовую БД; затем `restore-db.mjs` |
| Нет автоматического backup | Копии только вручную; копия не шифруется | Планировщик, ограниченный доступ, хранение вне машины |
| Нет смены пароля | Пароль задаётся при создании | Создать новую учётную запись |
| Нет формы изменения ролей | Только включение/отключение | Менять роли через API |
| CORS только localhost:5173 | Другой порт или хост не получит API | Согласованно менять прокси и CORS |
| Лимит входа в памяти процесса | 20 попыток в минуту на IP | Для одного экземпляра достаточно |

Из этого следует, что учебная среда не подтверждает промышленную защиту: шифрование канала БД, HTTPS, малопривилегированную роль СУБД, автоматическое восстановление и нагрузочные испытания нельзя считать выполненными.

## 7 Действия при сбоях

### 7.1 База данных недоступна

Симптомы: 503 в разделах, «База данных временно недоступна», вход возвращает 503; `/health` при этом может отвечать `ok`. Проверьте службу PostgreSQL, `pg_isready -h <хост> -p 5432`, `.env` (хост, порт, база, пользователь, `PGSSLMODE=disable`), место на диске и журнал PostgreSQL. Восстановите службу или подключение; повреждённую базу восстанавливайте в отдельную, а не поверх рабочей.

### 7.2 Сессия истекла

Симптом: переход на страницу входа, 401, потеря несохранённых данных. Причины: 8 часов, выход, отключение учётной записи или сотрудника, удалённая cookie. Войдите снова. Перезапуск API сессии не завершает: они хранятся в PostgreSQL; для принудительного завершения отключите пользователя.

### 7.3 Порт занят

Симптом: API не привязывает адрес; Vite сообщает, что 5173 занят, и завершается. Проверьте:

```powershell
Get-NetTCPConnection -LocalPort 5180 -State Listen
Get-NetTCPConnection -LocalPort 5173 -State Listen
```

Остановите процесс только после проверки, что это другой экземпляр MEDCORE: `Stop-Process -Id <PID>`. Не завершайте незнакомые процессы. При смене порта согласуйте прокси и CORS.

### 7.4 Прочие сбои

**Таблица 6 — Прочие сбои**

| Симптом | Причина | Действие |
|---|---|---|
| 429 при входе | Превышено 20 попыток в минуту | Подождать 60 секунд |
| 403 на действии | Роль или область | Проверить роль, не повторять |
| 409 на койке | Занята или пересечение | Обновить данные, выбрать другую койку |
| 500, есть `traceId` | Необработанная ошибка | Найти `traceId` в журнале API, передать разработчику |
| 503 или ошибка PDF | Нет подключения к БД или шрифта | Проверить журнал API и комплект шрифтов |

Если ни один пункт не объясняет сбой, сохраните время, раздел, действие и `traceId` и передайте разработчику. Пароль и строку подключения не передавайте.
